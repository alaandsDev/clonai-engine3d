# Capability-aware Topic Writer v1

Camada local, determinística e delimitada: `topic → analysis/capability match → strategy → outline → plain text → Semantic Engine 1.1 → Narrative Director → Auto Director → preflight/scoring/selection → fresh final preflight`. Não produz SemanticClaims, IDs de câmera/props, DirectedSequence ou demonstrações próprias. O provider implementado é somente DETERMINISTIC_LOCAL; LOCAL_MODEL/EXTERNAL_LLM são apenas nomes reservados no contrato.

```powershell
npm run writer:write -- examples/writer/water.json --out out/engine3d/writer
npm run check:writer
```

Entradas TopicScriptRequest v1 aceitam topic, language pt-BR, duração/palavras, factPolicy, fontes com proveniência/autorização, budgets e tom genérico. `script`, `claims`, direção e campos desconhecidos são rejeitados. O ID é metadata de transporte e não escolhe conteúdo. Defaults: 110–160 palavras, 40–60s, STRUCTURAL_ONLY. UNVERIFIED_CREATIVE é reservado e recusado.

style.tone é metadata reservada nesta versão; as variantes efetivas são dirigidas pelo arco. Clarificação de pronome na fonte exige também uma cadeia de transferência inequívoca reconhecida pelo Semantic Engine; fonte com outros sujeitos/operações desconhecidos conserva o texto em vez de substituir o referente por um palpite.

SOURCE_ONLY utiliza exclusivamente sourceMaterial com allowedForClaims=true. O realizer conserva texto das unidades fornecidas e permite três ajustes gramaticais reproduzíveis: tornar explícito o sujeito líquido único, introduzir com artigo indefinido os recipientes inferior/superior já nomeados e dividir a relativa “onde o nível aumenta” em frase própria. Isso não acrescenta causa, medida, objeto ou evento. Ambiguidade entre entidades não é corrigida por palpite. Cada fato extraído pelo Semantic Engine aponta para sourceMaterialId + sourceSpan original. Omissão é proibida por default; quando autorizada, permanece registrada. Contradição numérica/direcional é verificada usando eventos e quantities do parser existente, sem fact checker geral.

STRUCTURAL_ONLY não é pesquisa nem licença para fatos específicos. Os dois domínios geradores atuais são transferência esquemática de líquido e acúmulo ilustrativo de gelo no veículo. Tubo, origem/destino e progressão são convenções de representação declaradas; não explicam pressão, bombeamento, tempo, localização ou comportamento universal. A análise de tema usa o Semantic Engine existente e um vocabulário de admissibilidade fechado; resíduos desconhecidos recusam o pedido. Uma referência a água não autoriza ignorar outro conceito solicitado. Temas de pesquisa, fatos históricos e mecanismos exigem fonte ou permanecem unsupported, mesmo existindo geometria semelhante.

Capability profile deriva somente do grafo real: bundles exigem tags semânticas e conjunto completo de capabilities. O profile conserva IDs apenas como evidência de proveniência; outlines e realizer trabalham com operações/sujeitos abstratos. Remover FLOW realmente bloqueia o gerador de transferência. Registry é read-only. A biblioteca declara nove arcos, mas só PROCESS_EXPLAINER, PATH_JOURNEY, STATE_TRANSFORMATION, BEFORE_AFTER e QUESTION_REVEAL são elegíveis nos casos atuais. Quantidades/ranking/comparison não são fabricados para habilitar os demais.

O realizer é uma gramática composicional pequena, com formas de verbo/participantes e blocos neutros de atenção. Não há roteiro completo guardado por fixture, lookup por ID ou randomness. Três candidatos variam arco, posição de hook/pausa/objetivo e conclusão; a ordem física/causal é preservada. Isso é geração restrita e contém repetição editorial real, não linguagem aberta. `candidateStructuralSimilarity` compara cinco features com pesos iguais; similarity>=0.8 gera warning. A heuristic de naturalidade conta repetições de início/sentenças/conectores, extremos de comprimento e perguntas em excesso; não mede qualidade estética humana.

Preflight sempre chama analyzeNaturalScript, directNarrative e compileNarrative existentes. Fact audit valida o idioma de realização fechado contra o pedido original e a fonte autorizada, não apenas a provenance que um candidato declara. Fatos, números, nomes ou causas não licenciados causam hard rejection. Também rejeita NONE, ambiguidade crítica, ausência de facts visuais, gapRate>0.15, executableTimelineRate<0.85 e budgets excedidos. Os thresholds são configuráveis/versionados (writer-policy/1.0.0). Gap rate inclui bloqueios por dependência. PRIMARY preferido 4–8, máximo8; entidades centrais máximo4, domínios máximo2. Menos de quatro PRIMARY gera warning, sem preencher com fatos novos.

Scoring, somente depois dos hard gates: clareza semântica24, frames executáveis24, DIRECT18, continuidade8, baixa ambiguidade8, baixo gap8, naturalidade/pacing5, coerência3, baixa repetição2. Total100. Candidate rejeitado tem score−1; beleza textual nunca compensa fato inseguro. Empate exato usa candidate ID estável. Dados de candidatos rejeitados permanecem no resultado. Confidence e grounding são métricas internas, sem calibração estatística ou prova factual universal.

Revisão usa gaps reais, até duas vezes por candidato. Pode restaurar a forma canônica licenciada em uma referência falha ou remover contexto editorial problemático. Não troca fato SOURCE_ONLY por outro tema. Não há resolução automática geral de gaps científicos. `reviseDuration` ajusta somente contexto neutro após medição TTS, sem alterar rate/pitch, e respeita palavras/budget de revisões. `finalizeWriter` exige medição completa por unidade e reexecuta o preflight; seu fingerprint vincula resultado Writer, candidato final, revisões e plano medido. ProductionReady requer FULL, factualidade/policy aprovadas e duração dentro da faixa. READY estimado isoladamente não autoriza master de um plano parcial.

Writer é puro: sem filesystem, rede, relógio ou APIs. CLI/harnesses fazem I/O e medição fora do módulo. A narração edge-tts existente é executada apenas pelo piloto autorizado; não há serviço de escrita/pesquisa ou custo de geração. O piloto fica em out/engine3d/phase18, com pedidos, todos os candidatos/preflights, revisões, seleção, roteiro, grafos, planos, traces, vídeo e QA. Fases anteriores e renderer permanecem preservados.
